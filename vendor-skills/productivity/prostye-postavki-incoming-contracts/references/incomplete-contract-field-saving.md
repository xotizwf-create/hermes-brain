# Неполные входящие договоры: безопасное сохранение полей

## Когда применять
Документ содержит номер, стороны и часть финансовых условий, но не содержит даты подписания / даты заявки / полной спецификации. Полноценный контракт создавать нельзя: срок поставки станет вымышленным.

## Порядок
1. Сначала сохранить в `save_incoming_contract_document_fields` все подтверждённые реквизиты **одним полным вызовом**: номер, названия и ИНН сторон, НДС, доступные позиции, заметку.
2. Для отсутствующей даты передавать `contractDate: ""`.
3. Не передавать `deadlineText`, если он задаёт относительный срок (после подписания, после заявки): сервер может превратить его в абсолютную дату от текущего дня. Условие срока записать в `notes`.
4. Если надо очистить уже ошибочно рассчитанный дедлайн, в следующем вызове опять передать **весь подтверждённый набор полей**, вместе с `deadlineDate: ""` и без `deadlineText`. Частичный вызов сбрасывает неуказанные поля `parsedEdits`.
5. Прочитать результат сразу: дата договора и дедлайн должны остаться пустыми; `processed` должен остаться `false` до создания полноценной карточки.

## Проверка цен и количеств
В `parsedEdits.items` историческая UI-схема хранит количество в поле `price`, а цену — в `total`. Для проверки использовать только `itemsReadable` и `totalAmount` из ответа инструмента.
